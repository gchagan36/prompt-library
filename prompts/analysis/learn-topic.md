Teach me <TOPIC> so I actually own it, not so I can nod along. Structure:

1. **The problem it solves** — what breaks or hurts without it. Start here, not with definitions.
2. **The core model** — the 2–3 load-bearing concepts, each explained with a concrete example from my stack (Python/TypeScript, Linux/WSL, homelab) rather than a generic one.
3. **The misconception check** — the 2–3 things people commonly get wrong about this topic, and why the wrong version seems plausible.
4. **Worked example** — walk through a realistic scenario end to end, showing the decisions at each step.
5. **Test me** — ask me 3 questions that distinguish real understanding from recognition: one prediction ("what happens if…"), one design choice ("when would you pick X over Y"), one debugging scenario. Wait for my answers and correct them.
6. **Reference note** — after the Q&A, produce a dense one-page markdown note suitable for my Exocortex `Knowledge/` folder: the mental model, the decision rules, links to the primary docs. Written for future-me who half-remembers this conversation.
